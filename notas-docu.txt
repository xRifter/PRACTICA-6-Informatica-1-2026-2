Para empezar con lo mas basico, construir la estructura a partir del archivo. Lo primero que pensamos fue 3 variables tipo lista que seran la informacion base.

Planificando las fuciones 4 y 5 se noto que si se ordena a los estudiantes por sus promedios se perderia la corresponsabilidad con la estructura de datos, y si se ordena sobre la estructura de datos original se perderia la corresponsabilidad entre las 3 listas, o se perderia eficiencia por tener que ordenar 3 listas siempre. Para eso, se decidio que se crearia una lista de pares temporal, compuesta de sublistas con 2 elementos: (valor, indice), de esta forma cuando se ordene por promedios o cantidad de cursos el indice permita obtener de vuelta los datos del estudiante y las 3 variables originales nunca se mueven (a menos que se eliminen entradas). 

La funcion load_notes() retornara 3 listas en caso de ser exitosa, y un False en caso de presentar error, por tanto en main.py se debe de almacenar en una  variable para comprobar que no sea False. En caso de que ocurran errores durante la ejecucion de la funcion y para evitar tener que comprobar en todos los casos que se cierre el archivo aun si hay un return, se utilizara un gestor de contexto with para gestionar el cerrado. 
La funcion ignorara completamente las lineas vacias, tolerara una sola coma sobrante pero no espacios vacios. La funcion debera comprobar: ##PENDIENTE: AGREGAR COMPROBACION CURSOS REPETIDOS## que no haya documentos repetidos, que la cantidad  de filas con notas corresponda a la cantidad de documentos de identidad, y que la cantidad de notas en todas las filas corresponda a la cantidad de cursos. Asimismo debe de limpiar y comprobar que las filas de cursos y de documentos cumplan el formato especificado. Respecto a la lista de notas asociada a cada estudiante, se convertiran en numero directamete al cargar para validar que el valor sea valido (-1,-2 o del rango 0 - 5), evitando tener que convertiro de nuevo cada que se vayan a comprobar los archivos o realizar operaciones. La funcion rechaza el archivo completo si una comprobacion falla; se considero inicialmente que la funcion asumiera los datos faltantes en un intento de corregir el archivo (ej: estudiantes repetidos pero cantidad de filas coincide, o espacios en blancos leidos como cancelacion de curso), sin embargo consideramos que la ambiguedad de estas correciones comprometerian la integridad de los datos, por lo que elegimos mejor un rechazo completo si no se cumple la estructura. la funcion recibira un parametro booleano que indicara si se imprime o no un mensaje “EXITO: Archivo notas_estudiantes.csv importado exitosamente!"

Al momento de escribir load_notes, se noto que por la cantidad de comprobaciones necesarias para cargar un archivo, en los casos de error se repite mucho la misma estructura, por eso se creo una funcion auxiliar reutilizable para reportar errores al cargar archivos llamada load_error(), que recibira el nombre del archivo, el error especifico y opcionalmente la linea donde esta corrupto, e indicara en consola al usuario que ese archivo esta corrupto, devolviendo False para el retorno de load_notes().

A la hora de desempaquetar la funcion, primero se almacenara el retorno en una variable para comprobar que no sea False (si se desempaqueta directamente dara TypeError), en caso de que se retorne correctamente se desempaquetaran las variables en orden cursos, estudiantes, notas.
